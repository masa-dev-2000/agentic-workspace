# UX原則

- 常にUXを考慮する。
- ユーザーの操作・判断・学習・入力コストを最小化し、得られる効果を最大化する。
- 機能の多さではなく、ユーザーが目的を達成するまでの負担と成果で設計を判断する。
- UIの設計・実装・レビューを始める前に、このUX原則を必ず参照する。

## スクロール原則

- 画面全体・`body` のスクロールは原則として発生させない。
- 対応する各画面サイズのビューポート内に、主要情報と主要操作を収める。
- 情報が収まらない場合は、不要情報の削除、表示密度の調整、折りたたみ、タブ、ページ分割、モーダル、ドロワーなどの段階表示で解決する。
- 文字や操作対象を過度に縮小して収めることはしない。タップ領域と可読性を維持する。
- スクロールを避けるために、カードやコンテナを残り高さいっぱいへ無目的に引き伸ばしたり、過剰な空白を作ったりしない。情報量、余白、視線の流れ、操作位置のバランスを保つ。
- 部分スクロールは、他の合理的な表示方法がない場合に限り、明確に限定された領域内で使用する。
- 部分スクロールのスクロールバーは、役割を損なわない範囲で細く、低コントラストかつ視覚ノイズの少ない外観にする。
- スクロール可能であることが分からなくなるため、必要なスクロールバーを完全には隠さない。
- UIの完了前に、想定する各ビューポートで全画面スクロール、要素の欠落、固定要素の重なり、余白バランスの崩れがないことを実画像で検証する。

## AI Project Manager

- ユーザーがプロジェクトの管理、運営、監視、自動進行を依頼した場合、`project-orchestrator` を司令塔として使う。
- 司令塔は一つに保ち、専門エージェントは必要な作業だけを行う一時的な実行主体として扱う。
- プロジェクトの事実、計画、タスク、依存関係、担当、期限、検証結果は永続台帳を正本とし、会話記憶だけに依存しない。
- タスクは必要な能力と権限に基づき、AIエージェント、人間、外部サービスへ割り当てる。
- 安全で可逆、権限内、検証可能なAI作業は自動で進める。
- 人間にしかできない作業は、理由、準備済み資料、所要時間、期限、完了方法、遅延影響を付けて依頼する。
- 人間への判断と作業依頼は一つの優先キューへ集約し、結果を変える確認だけを求める。
- 重大、不可逆、対外的、本番、金銭、法務、削除に関わる操作は、実行直前に明示的な承認を得る。
- 完了は成果物や外部状態を検証してから記録し、計画や自己申告だけを完了根拠にしない。
- 催促は期限、依存関係への影響、過去の通知を考慮し、同じ内容を繰り返さない。
