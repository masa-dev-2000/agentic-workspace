レビューフェーズ。作成済みの企画・カリキュラム・教材を総合的にレビューし改善点を提示する。

引数: {講習名} - レビュー対象の講習名
例:
  /training-review "AI基礎講座"

## 手順

### Step 1: 成果物の収集

以下のファイルを読み込む:
- `.training/{講習名}/plan.md`
- `.training/{講習名}/curriculum.md`
- `.training/{講習名}/materials/` 配下の全ファイル
- `.training/{講習名}/exercises/` 配下の全ファイル

存在しないファイルがあれば、どのフェーズが未完了か報告し、先にそのフェーズを実行するよう案内。

### Step 2: レビュー観点

以下の観点でチェック:

#### 整合性
- 企画書の目的とカリキュラムの学習目標が一致しているか
- カリキュラムの各モジュールに対応する教材が揃っているか
- 演習がカリキュラムの学習目標をカバーしているか

#### 品質
- 対象者のレベルに合った内容か
- 時間配分は適切か（詰め込みすぎ / 余白がありすぎ）
- 説明の流れが論理的か

#### 実用性
- 演習は実際に実施可能か
- 必要な環境・ツールの準備手順は明記されているか
- 講師向けのガイド（進行メモ）は十分か

### Step 3: レビューレポートの作成

`.training/{講習名}/review.md` に以下を出力:

```markdown
# {講習名} - レビューレポート

## サマリー
- 全体評価: ◎ / ○ / △
- 主要な改善点の数: N件

## チェック結果

### 整合性
- [x] or [ ] 企画書の目的とカリキュラムの学習目標が一致
- [x] or [ ] 各モジュールに対応する教材が揃っている
- [x] or [ ] 演習が学習目標をカバー

### 品質
- [x] or [ ] 対象者のレベルに適合
- [x] or [ ] 時間配分が適切
- [x] or [ ] 説明の流れが論理的

### 実用性
- [x] or [ ] 演習が実施可能
- [x] or [ ] 環境・ツールの準備手順が明記
- [x] or [ ] 講師向けガイドが十分

## 改善提案
1. ...
2. ...

## 次のアクション
- ...
```

### Step 4: ステータス更新

`.training/{講習名}/plan.md` のステータスセクションを更新:
- [x] レビュー（review）

### Step 5: 改善の実施

ユーザーに改善提案を提示し、承認を得た改善点を各成果物に反映する。
